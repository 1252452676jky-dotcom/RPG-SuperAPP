## 1. Vision
A turn-based monster collecting + battling mini-game inside my habit tracker. Monsters come from several franchises, all normalized to one stat scale and one type system. Long-term, monsters link to my habit "Party" so real-life habits feel like progress. Visual style: flat 2D portraits/cards with simple VFX overlays (decoupled from monster art, keyed to generic elements like VFX_Fire, VFX_Slash).

Battle concept: 6-monster party, turn-based (3 active, 3 bench).

Run structure concept: rogue-lite. Runs start with early-stage monsters only; later stages/legendaries appear as the run progresses; a new run starts back at early stages. Shared Exp. Share XP across the party; auto-evolve at lore level thresholds. No IVs/EVs, no merge systems, no currency, no rarity.

## 3. Architecture
Hosting: GitHub Pages (static). Backend: Firebase project rpg-superapp-5404c, SDK 10.12.2 (ES modules from gstatic), Google sign-in + Firestore. Local testing: `npx serve .` → http://localhost:3000 (use localhost, not 127.0.0.1, for Firebase auth).

File layout:
index.html            HTML only
styles.css            former <style> block
app.js                former main <script>: habit app (party, quests, training, shop, categories/generators, checklists, calendar, holidays, streak bonus, export/import + merge engine)
cloud.js              former <script type="module">: Firebase auth + habit sync
game/gacha.js         Monster Lab tab (IIFE, exposes window.Gacha)
game/game-cloud.js    syncs game state to its own Firestore doc
data/                 generated by build script (committed)
tools/build-data.mjs  Node build script (committed)
tools/.cache/         API cache (gitignored)

Script load order at end of <body>: app.js → game/gacha.js → cloud.js (module) → game/game-cloud.js (module).

Integration hook (the only edit to app.js), in render() before the "Unknown tab" fallback:
  else if (window.GameTabs && GameTabs[t]) GameTabs[t](c);
gacha.js pushes {id:'gacha', label:'Monster Lab', icon:'fa-dragon'} into fixedTabs and registers GameTabs.gacha.

Existing habit app facts that matter:
- appState is synced as ONE Firestore doc users/{uid} (1.5 s debounce, updatedAt last-write-wins, dirtyKey dedup, merge engine on first sync).
- render() calls save() every time → game code must never call save() except deliberately (e.g. promote to Party).
- grantXP(amount,'even') splits XP across ALL appState.party members → monsters must NOT be auto-added to party (dilution). Box/Team are separate; "Promote to Party" is a manual copy.
- Main Export JSON does not yet include game data (Monster Lab has its own "Export game JSON").

Firestore:
- users/{uid}: habit state (unchanged).
- users/{uid}/game/main: { state: {v, box, team, updatedAt}, updatedAt }. 5 s debounce; push skipped if JSON of [box, team] unchanged (MUST add overrides to this key when corrections ship). onSnapshot applies newer remote state.
- Rules: match /users/{uid}/{document=**} { allow read, write: if request.auth != null && request.auth.uid == uid; }
- Cost: static monster data never touches Firestore. Expected usage is far below free tier (50k reads / 20k writes per day, 1 GiB). Battle/run state must stay local; push only on meaningful events (end of battle/run, catch, evolve).

Local storage:
- localStorage key rpg_gacha_v1: full game state including ui.
- IndexedDB db 'rpg_gacha', store 'kv': 'monsters' = {version, list} (re-downloaded only when data/index.json version changes); TCGdex caches (tcgp_sets, tcg_<dex>) with 7-day expiry.
- No service worker yet (optional later for full offline).

## 4. Data pipeline (tools/build-data.mjs)
Run: `node tools/build-data.mjs` (Node 18+; I have the LTS installed). First run ~10–25 min (PokéAPI ~4k requests, concurrency 6, cached); reruns take seconds. Delete tools/.cache to refresh. If Palworld/Digimon fail, the previous file is kept. Pokémon is required (it is the reference scale).

Outputs in /data: index.json {version, franchises:{fr:{file,count}}}, monsters.<fr>.json, learnsets.<fr>.json, moves.<fr>.json.

Monster record:
{ key, fr, name, ja, spName, dex, img, types[], typesOrig, raw[6], base[6], bst, stage, tier, final, legendary, special, isDefault, evo:[{to,lv}],
  + Digimon: fields[], attribute, level   + Palworld: rarity }
Stat order everywhere: HP, Atk, Def, SpA, SpD, Spe.

Keys (permanent IDs used by box/team/overrides):
- Pokémon `pkmn:<api-name>` (e.g. pkmn:raichu-alola)
- Palworld `pal:<codename>`
- Digimon `digi:<slug-of-name>`; on a name clash the later DAPI id gets `-<id>` appended. Old `digi:<number>` keys are auto-migrated in gacha.js via dex lookup.

Learnsets: { key: [[moveId, level|null], …] }.
Moves:
- Pokémon {name,type,cat,power,acc,pp,prio}, level-up moves from the newest version group; alt forms with none fall back to the default form.
- Palworld {name,type,typeOrig,cat,power,cd,desc}.
- Digimon {name, jp, desc}: no power/type/category.

### Tiers (spawn pools)
T1 Early, T2 Mid, T3 Late, T4 Legend/Special.
- Pokémon:
  - legendary/mythical or Mega/Gmax/Primal/Eternamax → T4
  - single-stage species by BST (<400 T1, <500 T2, else T3)
  - otherwise tier = clamp(stage, 1..3); baby stage 0 → T1
- Palworld: by rarity (≥11 T4, ≥8 T3, ≥5 T2, else T1). Thresholds may need tuning from the printed histogram.
- Digimon by level:
  | Level | Tier | Stage | Power percentile |
  |---|---|---|---|
  | Baby I | T1 | 0 | 0.05 |
  | Baby II | T1 | 0 | 0.12 |
  | Child | T1 | 1 | 0.28 |
  | Adult | T2 | 2 | 0.48 |
  | Armor | T2 | 2 | 0.52 |
  | Hybrid | T3 | 3 | 0.66 |
  | Perfect | T3 | 3 | 0.70 |
  | Ultimate | T4 | 4 | 0.90 |
  | Unknown | T2 | 2 | 0.45 |

### Evolution
- Pokémon: chains from PokéAPI; regional forms evolve into the same region's form when it exists. Stone/trade/friendship evolutions have lv = null and need a fallback rule in Phase 2.
- Megas/Gmax have no evo links.
- Digimon: nextEvolutions (branching, lv null).
- Palworld: none.

### Stat normalization
- Pokémon: base = raw (capped 255).
- Other franchises:
  1. Scale each stat by (Pokémon median for that stat / franchise median).
  2. Take the monster's percentile of its scaled total within its own franchise. Digimon use their level percentile ± 0.04 jitter instead.
  3. Target total = the Pokémon BST value at that same percentile.
  4. base_i = clamp(round(target × share_i), 5, 255).
- Unified 1,000-cap display: statAt(base, lv) = round(1000 × base/255 × (0.2 + 0.8 × lv/100)).

Palworld raw mapping: [hp, meleeAttack, defense, shotAttack, defense, runSpeed].

Digimon generated raw stats:
- Seeded RNG keyed by name, so stats are identical every build.
- Per-stat bias by attribute (+%): Vaccine Def/SpD +25; Virus Atk +25, SpA +15; Data SpA +25, Spe +15; Free/other HP +10.
- raw = 100 × (1 + bias) × (0.75..1.25 random).

### Types
- Global standard: Pokémon's 18 types.
- Palworld mapping: Neutral→normal, Leaf→grass, Earth→ground, Electricity→electric; Fire/Water/Ice/Dark/Dragon map directly.
- Dual-type rule (decided): split into single types and multiply Pokémon-style, cap 4×.
- Digimon auto-typing (digiTypes), scored:
  | Evidence | List | Points |
  |---|---|---|
  | Each skill's name + description | ELEMENT_WORDS | 3 |
  | Species "types" text | ELEMENT_WORDS | 2 |
  | Species text, only types not already hit in that text | DIGI_KEYWORD | 1 |
  | Each Field | DIGI_FIELD | 1 (Normal ignored) |
  - Winner = highest score.
  - Second type only if: not normal, score ≥ 2, and ≥ 60% of the winner. Empty → ['normal'].
  - Accuracy is roughly 50–70%; manual corrections are planned.
